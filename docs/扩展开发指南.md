# JsMacrosPlus 扩展（Addon）开发指南

> 面向 JsMacrosPlus（Minecraft 26.2 / Fabric）的**独立扩展**开发者。

## 1. 扩展是什么

**Addon** 是一个独立的 Fabric mod，为 JsMacrosPlus 的脚本系统提供新能力：

| 能力 | 说明 |
|---|---|
| **脚本库** | 注册后成为脚本全局对象（如 `NbtIo.readFile(...)`），把 Java 方法暴露给 JS/TS/Python |
| **事件** | 自定义事件（如 `ExampleOpenContainer`），脚本用 `JsMacros.on("EventName", ...)` 监听 |
| **对象包装（Helper）** | 把 Java 对象包装成脚本友好的形式暴露字段与方法 |
| **配置** | 注册配置类，持久化到 `options.json` 并显示在设置界面 |
| **MC 事件挂钩** | 通过 Mixin 注入游戏代码，在合适时机触发自定义事件或调用库方法 |

**架构**：

```
┌─────────────────────────────────────────────────────────┐
│  Addon (fabric mod)                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐   │
│  │ 库类 @Library │  │ 事件 @Event  │  │ mixin (MC hook)│  │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘   │
│         │                 │                  │           │
│  fabric.mod.json entrypoints: "jsmacrosplus" │           │
└─────────┼─────────────────┼──────────────────┼───────────┘
          ▼                 ▼                  ▼
    jsmacrosplus (主 mod)  ── FabricLoader.getEntrypointContainers("jsmacrosplus")
          │                 │                  │
          ▼                 ▼                  ▼
    Core.addLibrary   Core.addEvent    事件触发 → 脚本
```

**发现方式**（两种）：

| 方式 | 位置 | 机制 |
|---|---|---|
| **Fabric mod（推荐）** | 游戏 `mods/` 文件夹 | `fabric.mod.json` 声明 `"jsmacrosplus"` entrypoint，主 mod 启动时发现并初始化 |
| **传统扩展** | `config/jsMacros/Extensions/` | `META-INF/services/xyz.wagyourtail.jsmacros.api.Extension` 声明实现类 |

> 核心原则：Addon 编译时**只依赖 `jsmacrosplus-api`**（纯 JDK 构件，零 MC/Fabric 依赖），运行时通过接口与主 mod 交互，互不侵入。

## 2. 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | **21** | 运行 Gradle 构建（Gradle 8.14.4 不支持 JDK 25/26 作为守护 JVM） |
| JDK | **25/26**（普通 JDK，如 Zulu 26） | 编译 toolchain（Gradle 自动解析）与游戏运行 |
| Gradle | 8.14.4（wrapper 自带） | 无需单独安装 |
| Minecraft | 26.2（Fabric） | Fabric Loader ≥ 0.15.0（推荐 0.19.3） |

> **关于 GraalVM JDK**：游戏**不要**用 GraalVM JDK 25 运行——graal-sdk 24.0.1 与 JDK 25 的 JVMCI 不兼容，会导致 `LibGraal` 初始化崩溃（`NoSuchFieldError: IS_BUILDING_NATIVE_IMAGE`）。用普通 JDK（无 JVMCI）时 Graal 引擎自动以解释模式运行，完全可用。详见 [FAQ](#16-常见问题faq)。

## 3. 获取 API

两种方式任选其一：

### 方式 A：JitPack（推荐，无需本地安装）

API 构件已发布在 JitPack（根模块坐标）：

```kotlin
repositories {
    maven("https://jitpack.io")
    mavenCentral()
}
dependencies {
    implementation("com.github.Melationin:JsMacros262:2.0.1")
}
```

### 方式 B：mavenLocal（本地开发）

在 JsMacrosPlus 仓库根目录执行：

```bash
JAVA_HOME="C:\Program Files\Java\jdk-21" ./gradlew :jsm-api:publishToMavenLocal
```

然后依赖（本地坐标，artifactId 为 `jsmacrosplus-api`）：

```kotlin
repositories { mavenLocal(); mavenCentral() }
dependencies {
    implementation("xyz.wagyourtail.jsmacros:jsmacrosplus-api:2.0.1")
}
```

**API 包含的类**（包 `xyz.wagyourtail.jsmacros.api`）：

| 类/接口 | 用途 |
|---|---|
| `Extension` | 扩展入口接口 |
| `Core` | 扩展视角的运行时接口（注册库/事件/Helper/配置） |
| `BaseLibrary` + `@Library` | 脚本库基类与注解 |
| `BaseEvent` + `@Event` + `EventFilterer` | 事件基类、注解与过滤器 |
| `BaseHelper<T>` | 对象包装基类 |
| `Config` | 配置管理器接口 |
| `LibraryExtension` | 可选标记接口（声明式提供库类） |

## 5. 扩展入口：Extension 接口

```java
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.Core;
import xyz.wagyourtail.jsmacros.api.Extension;

public class MyAddon implements Extension {

    /** 保存 Core 实例，供 mixin 等需要触发事件的代码使用。 */
    public static Core core;

    /** 扩展的唯一名称（用于嵌套依赖文件命名等）。 */
    @Override
    public String getExtensionName() {
        return "my-addon";
    }

    /** 兼容的核心版本范围（默认均为 "2.0.0"）。 */
    @Override
    public String minCoreVersion() {
        return "2.0.0";
    }

    @Override
    public String maxCoreVersion() {
        return "2.0.1";
    }

    /** 扩展加载时调用一次：在此注册库、事件、Helper 与配置。 */
    @Override
    public void init(Core runner) {
        core = runner;
        runner.addLibrary(MyLib.class);        // 注册脚本库
        runner.addEvent(MyEvent.class);        // 注册事件
        runner.registerHelper(SomeType.class, SomeTypeHelper.class);  // 注册对象包装
        try {
            runner.getConfig().addOptions("myaddon", MyConfig.class); // 注册配置
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
        System.out.println("My addon initialized");
    }
}
```

**接口方法一览**：

| 方法 | 必选 | 说明 |
|---|---|---|
| `String getExtensionName()` | ✅ | 扩展唯一名 |
| `void init(Core runner)` | ✅ | 初始化入口 |
| `String minCoreVersion()` | 可选（默认 `"2.0.0"`） | 兼容的最小核心版本 |
| `String maxCoreVersion()` | 可选（默认 `"2.0.0"`） | 兼容的最大核心版本 |
| `Set<String> getDependencies()` | 可选（默认空） | 嵌套依赖 jar 路径；默认读取 `jsmacros.ext.<name>.json` |
| `Map<String,String> getTranslations(String lang)` | 可选（默认空） | 语言翻译 |

**可选接口 `LibraryExtension`**（声明式注册库，与 `init` 里手动 `addLibrary` 等价）：

```java
public class MyAddon implements LibraryExtension {
    @Override
    public Set<Class<? extends BaseLibrary>> getLibraries() {
        return Set.of(MyLib.class);
    }
    // ...其余同 Extension
}
```

## 6. 脚本库：BaseLibrary 与 @Library

### 6.1 基本写法

```java
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.BaseLibrary;
import xyz.wagyourtail.jsmacros.api.Core;
import xyz.wagyourtail.jsmacros.api.Library;

/**
 * @Library("MyLib") → 脚本里出现全局对象 MyLib
 */
@Library("MyLib")
public class MyLib extends BaseLibrary {

    // BaseLibrary 已提供 public final Core runner 字段
    public MyLib(Core runner) {
        super(runner);
    }

    /** 库方法：public 实例方法，自动暴露给脚本。 */
    public String hello(String name) {
        return "Hello, " + name + "!";
    }

    /** 支持重载。 */
    public String hello() {
        return hello("world");
    }

    /** 支持基本类型参数与返回值。 */
    public double add(double a, double b) {
        return a + b;
    }

    /** 可以访问宏文件夹等运行时信息（runner 字段）。 */
    public String macroFolder() {
        return runner.getMacroFolder();
    }
}
```

### 6.2 脚本侧调用

```js
MyLib.hello("JsMacrosPlus");   // "Hello, JsMacrosPlus!"
MyLib.hello();                 // "Hello, world!"（重载）
MyLib.add(1.5, 2.5);           // 4
MyLib.macroFolder();           // 宏文件夹绝对路径
```

### 6.3 库方法规则（重要）

| 规则 | 说明 |
|---|---|
| **`public` 修饰** | 只有 `public` 实例方法暴露给脚本；`private`/`protected`/`static` 不暴露 |
| **参数类型** | 基本类型（`int`/`double`/`boolean`/`String`/`long` 等）直接映射；复杂 Java 对象按第 8 章规则包装 |
| **返回值** | 基本类型直接返回；Java 对象会被包装成脚本对象（MC 类由主 mod 的 Helper 体系包装，如 NBT 的 `CompoundTag` 自动包装后可用 `.get("key")`） |
| **异常** | 方法可 `throws` 已检查异常；脚本侧抛错时异常会被包装为 JS 异常 |
| **命名** | 方法名就是脚本属性名（驼峰风格）；建议使用语义化命名 |
| **重载** | 支持重载，脚本按参数个数/类型解析 |

### 6.4 脚本库与语言

- 库对 JS / TS / Python 统一可用（`@Library` 名即各语言的全局对象名）。
- TS 的类型声明由 [genTSDoc](#11-typescript-类型文档gentsdoc) 生成。

## 7. 事件：BaseEvent 与 @Event

### 7.1 事件类

```java
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.BaseEvent;
import xyz.wagyourtail.jsmacros.api.Core;
import xyz.wagyourtail.jsmacros.api.Event;

/**
 * @Event("MyEvent") → 脚本用 JsMacros.on("MyEvent", ...) 监听
 * 事件的 public final 字段会成为脚本侧的事件属性
 */
@Event("MyEvent")
public class MyEvent extends BaseEvent {

    public final String message;
    public final int count;

    public MyEvent(Core runner, String message, int count) {
        super(runner);
        this.message = message;
        this.count = count;
    }
}
```

### 7.2 触发事件

从**库方法**或 **mixin** 中触发（`BaseEvent.trigger()` 会运行所有监听该事件的脚本）：

```java
// 库方法里触发
public void fire(String message) {
    new MyEvent(runner, message, 42).trigger();
}

// mixin 里触发（需要保存的 Core 实例）
new MyEvent(MyAddon.core, "container opened", 1).trigger();
```

### 7.3 脚本侧监听

```js
// 事件宏：K → 事件 → + → 选 "MyEvent" → 选文件
// 整个文件执行，event 全局变量可用
if (event.message === "container opened") {
    Chat.log("count: " + event.count);
}

// 或注册式监听（回调必须用 JavaWrapper.methodToJava 包装）
JsMacros.on("MyEvent", JavaWrapper.methodToJava((e) => {
    Chat.log(e.message + " / " + e.count);
}));
```

### 7.4 `@Event` 注解字段详解

```java
@Event(
    value = "MyEvent",          // 事件名（脚本侧唯一）
    oldName = "",               // 旧名（事件改名时的兼容别名，可选）
    cancellable = false,        // 是否可被脚本取消
    joinable = false,           // 是否可被脚本 join（阻塞等待脚本处理完）
    filterer = EventFilterer.class  // 事件过滤器（可选，见 7.6）
)
```

### 7.5 可取消事件

```java
@Event(value = "CancellableEvent", cancellable = true)
public class CancellableEvent extends BaseEvent {
    public final String data;
    public CancellableEvent(Core runner, String data) {
        super(runner);
        this.data = data;
    }

    /** 触发后检查是否被脚本取消，决定后续逻辑。 */
    public void fireAndAct() {
        this.trigger();
        if (this.isCanceled()) {
            System.out.println("cancelled by script, abort");
        } else {
            System.out.println("proceed");
        }
    }
}
```

脚本侧：

```js
JsMacros.on("CancellableEvent", JavaWrapper.methodToJava((e) => {
    e.cancel();    // 只有 cancellable=true 的事件可取消，否则抛异常
}));
```

> 注意：`cancel()` 是 `final` 方法，事件类不能覆写；非可取消事件调用 `cancel()` 会抛 `UnsupportedOperationException`。

### 7.6 事件过滤器 `EventFilterer`

在事件**分发给脚本之前**做条件判断（例如按游戏状态过滤）：

```java
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.BaseEvent;
import xyz.wagyourtail.jsmacros.api.Event;
import xyz.wagyourtail.jsmacros.api.EventFilterer;

public class InGameFilter implements EventFilterer {

    /** 是否对这个事件名启用过滤。 */
    @Override
    public boolean canFilter(String event) {
        return event.equals("MyEvent");
    }

    /** 返回 true 才把事件分发给脚本。 */
    @Override
    public boolean test(BaseEvent event) {
        return event instanceof MyEvent my && my.count > 0;
    }
}

// 事件上挂过滤器
@Event(value = "MyEvent", filterer = InGameFilter.class)
public class MyEvent extends BaseEvent { ... }
```

## 8. 对象包装：BaseHelper

当库方法返回/接收**自定义 Java 类型**时，可以注册 Helper，把对象包装成脚本友好的形态：

```java
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.BaseHelper;

/** 原始类型 */
public class Point {
    public final double x, y;
    public Point(double x, double y) { this.x = x; this.y = y; }
}

/** 包装类型：脚本侧看到的是包装类的方法 */
public class PointHelper extends BaseHelper<Point> {
    public PointHelper(Point base) { super(base); }

    public double getX() { return base.x; }
    public double getY() { return base.y; }

    public double distance(PointHelper other) {
        double dx = base.x - other.base.x, dy = base.y - other.base.y;
        return Math.sqrt(dx * dx + dy * dy);
    }
}
```

注册（`init` 里）：

```java
runner.registerHelper(Point.class, PointHelper.class);
```

库方法使用：

```java
public PointHelper makePoint(double x, double y) {
    return new PointHelper(new Point(x, y));   // 返回包装类型
}
```

脚本侧：

```js
const p = MyLib.makePoint(1, 2);
p.getX();            // 1
p.getY();            // 2
MyLib.makePoint(3, 4).distance(p);   // 2.828...
```

**Helper 规则**：

| 规则 | 说明 |
|---|---|
| 泛型基类 | `BaseHelper<T>`，`T` 是原始类型 |
| `base` 字段 | `protected`，包装的原始对象 |
| `getRaw()` | 取回原始对象 |
| `equals/hashCode` | 已委托给原始对象 |
| 注册 | `Core.registerHelper(原始类型, Helper类型)` 全局生效 |

## 9. 配置：Config

配置类是**普通 POJO**：注册后自动持久化为 JSON（`options.json`），并显示在主 mod 的设置界面。

```java
package com.example.myaddon;

public class MyConfig {
    public String greeting = "Hello";
    public int maxCount = 10;
    public boolean verbose = false;
}
```

注册（`init` 里）：

```java
runner.getConfig().addOptions("myaddon", MyConfig.class);
```

读取与保存：

```java
// 任意位置（库方法/mixin）读取共享配置实例
MyConfig cfg = runner.getConfig().getOptions(MyConfig.class);
cfg.maxCount = 20;
runner.getConfig().saveConfig();   // 立即落盘
```

**Config 接口方法**：

| 方法 | 说明 |
|---|---|
| `void addOptions(String key, Class<?> optionClass)` | 注册配置类（key 是 options.json 里的键），已存在则从磁盘加载 |
| `<T> T getOptions(Class<T>)` | 获取共享实例 |
| `void saveConfig()` | 保存全部配置到磁盘 |

## 10. Mixin 集成

Addon 是标准 Fabric mod，mixin 能力原生可用。典型用途：挂钩 MC 事件 → 触发自定义事件。

```java
package com.example.myaddon.mixin;

import com.example.myaddon.MyAddon;
import com.example.myaddon.MyEvent;
import net.minecraft.client.Minecraft;
import net.minecraft.client.gui.Gui;
import net.minecraft.client.gui.screens.Screen;
import net.minecraft.client.gui.screens.inventory.AbstractContainerScreen;
import org.spongepowered.asm.mixin.Mixin;
import org.spongepowered.asm.mixin.injection.At;
import org.spongepowered.asm.mixin.injection.Inject;
import org.spongepowered.asm.mixin.injection.callback.CallbackInfo;

/**
 * 示例：打开任何容器界面（箱子/熔炉…）时触发 MyEvent。
 */
@Mixin(Gui.class)
public class GuiMixin {

    @Inject(method = "setScreen", at = @At(value = "INVOKE", target = "Lnet/minecraft/client/gui/screens/Screen;added()V"))
    private void myAddon$onOpenScreen(Screen screen, CallbackInfo ci) {
        if (screen instanceof AbstractContainerScreen<?> container && MyAddon.core != null) {
            new MyEvent(MyAddon.core, "container opened", 1).trigger();
        }
    }
}
```

要点：

| 要点 | 说明 |
|---|---|
| 命名空间 | mixin 方法名前缀建议 `你的modid$`（如 `myAddon$`），避免与其他 mod 冲突 |
| 包声明 | `@Mixin` 类必须放在 `my-addon.mixins.json` 声明的 `package` 下 |
| 触发事件 | 用静态保存的 `MyAddon.core` 构造事件并 `trigger()` |
| 目标方法 | 使用 **Mojang 映射**命名（`unimined` 已配置 `mojmap()`，写 `setScreen` 而非 `method_...`） |

## 11. TypeScript 类型文档（genTSDoc）

为 `@Library` / `@Event` 类生成 `.d.ts` 类型声明（供编辑器自动补全 / 类型提示）。

### 前置

doclet 需发布到 mavenLocal（JsMacrosPlus 仓库内执行一次）：

```bash

```

### 使用

```bash
JAVA_HOME="C:\Program Files\Java\jdk-21" ./gradlew genTSDoc
```

产出：`build/typescript/headers/<name>-<version>.d.ts`（本项目配置为 `my-addon-1.0.0.d.ts`）。

### 生成内容示例

```ts
declare namespace Events {
    interface MyEvent extends BaseEvent {
        readonly message: string;
        readonly count: number;
    }
}

declare namespace MyLib {
    function hello(name: string): string;
    function hello(): string;
    function add(a: number, b: number): number;
    function macroFolder(): string;
}
```

### 选项说明（build.gradle.kts 中已配置）

| 选项 | 值 | 含义 |
|---|---|---|
| `-v` | `1.0.0` | 版本号（输出文件名一部分） |
| `-name` | `my-addon` | 文件名前缀（默认 `JsMacros`，避免与主 mod 头文件混淆） |
| `-no-globals` | （布尔） | **必须开启**：跳过全局声明（`declare const context/event/file`、枚举类型、Packages 树），只输出本 Addon 自己的库/事件，这样可与主 mod 的 `JsMacros-*.d.ts` **合并**而不产生重复标识符 |

想让其他开发者直接依赖你的 Addon API？把它发布到 JitPack（代码在 GitHub 即可）：

1. **仓库设为公开**
2. **打 tag 并推送**：

```bash
git tag 1.0.0
git push origin 1.0.0
```

3. **触发构建**：打开 `https://jitpack.io/#<user>/<repo>/1.0.0` → 点 **Get it**

> 若你的项目是 Gradle 多模块、且只有 `jsm-api` 这类子模块要发布，注意：
> - JitPack 靠 **pom.xml** 发布构件（`assemble` 不产 pom，会 "No build artifacts found"）→ `install` 命令要用 `./gradlew :<模块>:publishToMavenLocal`
> - 发布坐标是**根模块坐标**（`com.github.<user>:<repo>:<tag>`），不是子模块坐标

4. **他人依赖**：

```kotlin
repositories { maven("https://jitpack.io") }
dependencies { implementation("com.github.<user>:<repo>:1.0.0") }
```

## 14. 脚本侧使用示例

假设 Addon 提供了 `MyLib` 库、`MyEvent` 事件（含 `message`/`count` 字段）：

### JavaScript

```js
// 库
const msg = MyLib.hello("world");
Chat.log(msg);

// 事件
JsMacros.on("MyEvent", JavaWrapper.methodToJava((e) => {
    Chat.log(`event: ${e.message} #${e.count}`);
}));
```

### TypeScript

```ts
// 与 JS 相同；配合 genTSDoc 生成的 .d.ts 可获得类型提示
const msg: string = MyLib.hello("world");
JsMacros.on("MyEvent", JavaWrapper.methodToJava((e) => {
    Chat.log(e.message);
}));
```

### Python

```python
# 库
msg = MyLib.hello("world")
Chat.log(msg)

# 事件
def on_event(e):
    Chat.log("event: " + e.message)

JsMacros.on("MyEvent", JavaWrapper.methodToJava(on_event))
```

> 所有语言中，**事件回调必须用 `JavaWrapper.methodToJava(fn)` 包装**（回调参数是 `MethodWrapper` 类型，JS 函数不能直接传入）。

```java
// ============ MyAddon.java（入口） ============
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.Core;
import xyz.wagyourtail.jsmacros.api.Extension;

public class MyAddon implements Extension {
    public static Core core;

    @Override
    public String getExtensionName() { return "my-addon"; }

    @Override
    public void init(Core runner) {
        core = runner;
        runner.addLibrary(MyLib.class);
        runner.addEvent(MyEvent.class);
        runner.registerHelper(Point.class, PointHelper.class);
        try {
            runner.getConfig().addOptions("myaddon", MyConfig.class);
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}

// ============ MyLib.java（脚本库） ============
package com.example.myaddon;

import xyz.wagyourtail.jsmacros.api.BaseLibrary;
import xyz.wagyourtail.jsmacros.api.Core;
import xyz.wagyourtail.jsmacros.api.Library;

@Library("MyLib")
public class MyLib extends BaseLibrary {

    public String hello(String name) { return "Hello, " + name + "!"; }

    /** 触发事件示例 */
    public void fire(String message) {
        MyConfig cfg = runner.getConfig().getOptions(MyConfig.class);
        new MyEvent(runner, message, cfg.maxCount).trigger();
    }

    /** Helper 返回示例 */
    public PointHelper makePoint(double x, double y) {
        return new PointHelper(new Point(x, y));

}

public class MyConfig {
```

## 16. 常见问题（FAQ）

### 1. 游戏报 `NoClassDefFoundError: xyz.wagyourtail.jsmacros.api.XXX`
Addon 缺少 `jsmacrosplus-api` 运行时依赖——Addon 的 jar 本身不含 API 类，必须由主 mod 提供。检查：主 mod 是否已装入 `mods/`、`depends` 是否写了 `"jsmacrosplus"`。

### 2. 加载时报 `requires jsmacrosplus ... but it is not installed`（或 `jsmacros`）
- `depends` 写成了 `"jsmacros"` → 主 mod 的 id 是 **`jsmacrosplus`**
- 或 mods 文件夹里的主 mod 是旧版/旧名 jar

### 3. Addon 没被加载（日志无 `Loaded JsMacros extension`）
检查三点：
- `fabric.mod.json` 的 entrypoint 键必须是 **`"jsmacrosplus"`**（不是 `"jsmacros"`）
- entrypoint 类名与 `implements Extension` 的类一致
- `init()` 里注册内容正常（异常会被捕获并打印 `Failed to load JsMacros extension`）

### 4. 游戏崩溃 `NoSuchFieldError: Services does not have member field 'boolean IS_BUILDING_NATIVE_IMAGE'`
**不要用 GraalVM JDK 25 运行游戏**。graal-sdk 24.0.1 与 JDK 25 的 JVMCI 不兼容（`LibGraal` 初始化崩溃）。改用**普通 JDK 25/26**（无 JVMCI，Graal 自动解释模式运行）。若坚持 GraalVM JDK，需给 JVM 加 `-XX:-EnableJVMCI`，或升级 graal-sdk 到匹配版本。

### 5. 构建报错 `generateWebDoc` 失败
文档任务与代码无关（依赖外网 javadoc 链接）。构建发布 jar 用 `./gradlew fabricJar` 或 `build -x test -x generateWebDoc`（Addon 项目不含此任务，不受影响）。

### 6. 事件脚本不触发
- 事件宏触发时**整个文件执行**，用 `event` 全局变量取数据（不需要 `JsMacros.on`）
- `JsMacros.on("X", fn)` 的回调必须用 **`JavaWrapper.methodToJava(fn)`** 包装
- 确认事件名一致（`@Event` 的 value 与 `JsMacros.on` 的字符串）
- 确认事件已 `trigger()`（mixin 里触发需要 `MyAddon.core` 非空——主 mod 初始化完成前不会触发）

### 7. `cancel()` 抛 `UnsupportedOperationException`
事件没有声明 `cancellable = true`。取消能力必须在 `@Event` 注解中开启。

### 8. 改完 Java 代码后脚本侧看不到新方法
重新构建 jar 并替换 `mods/` 里的文件，重启游戏（脚本运行时绑定的是加载时的库类）。

### 9. Addon 之间方法名/事件名冲突怎么办
脚本库/事件名全局唯一。命名时加前缀（如 `MyAddon_xxx`）或使用 `@Event(oldName=...)` 迁移旧名。

### 10. 如何让玩家也能用我的 Addon
发布 jar 到 GitHub Release（`softprops/action-gh-release` 等），玩家下载后放入 `mods/`。API 构件如需给其他开发者用，见[第 13 章](#13-发布到-jitpack)。
